# USER RULES - 开发红线

> **⚠️ 重要提醒：在开始任何开发工作之前，必须阅读并遵循本文件！**

## 1. 不调查不开发
- 任何开发、重构、优化前，必须先调查现有项目状态。
- 未调查直接开发，代码审查一律不通过。

## 2. 关键信息必验证
- 路径、文件名、依赖、接口等关键信息，必须实际验证。
- 发现凭经验操作、未验证即开发，代码审查一律不通过。

## 3. 架构和规范优先
- 所有开发必须遵循现有架构和目录规范。
- 重大变更需团队讨论并记录。

## 4. 变更需自检
- 每次提交前，必须完成自检清单（见docs/development_rules.md）。
- 未自检或自检不合格，代码审查一律不通过。

## 5. 团队沟通优先
- 重要变更、疑难问题、架构调整，必须先沟通再执行。
