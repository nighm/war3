# 🚨 开发规则快速检查卡

## ⚡ 开发前必读检查清单

在开始任何开发任务之前，请完成以下检查：

### 1️⃣ 预开发分析检查
- [ ] **项目状态分析**：检查了项目目录结构和现有文件
- [ ] **功能覆盖评估**：评估了现有功能是否满足需求
- [ ] **开发方式确定**：选择了集成/修改 vs 新建

### 2️⃣ 信息验证检查
- [ ] **路径验证**：程序化验证了所有关键路径
- [ ] **配置确认**：验证了配置文件的正确性
- [ ] **用户确认**：对于无法验证的信息获得了用户确认

### 3️⃣ 架构遵循检查
- [ ] **架构理解**：理解了现有项目架构和代码模式
- [ ] **集成方式**：选择了合适的集成方式（修改/扩展现有组件）
- [ ] **一致性保持**：保持了代码组织和风格的一致性

## 🚫 禁止行为

### ❌ 直接开发综合征
- 收到需求后立即开始编码
- 不分析现有状态和功能

### ❌ 假设信息综合征
- 使用未经验证的路径、配置或数据
- 对关键信息进行假设

### ❌ 架构忽视综合征
- 创建与现有架构不一致的新文件
- 忽视现有的代码组织模式

## ✅ 正确做法

### 🔍 分析优先
```python
# 1. 先分析项目结构
list_dir(relative_workspace_path=".")

# 2. 检查相关文件
read_file(target_file="existing_file.py", ...)

# 3. 评估现有功能
# 4. 确定最佳开发方式
```

### 🔒 验证优先
```python
# 1. 程序化验证
if not Path(user_path).exists():
    print("❌ 路径不存在，请确认")

# 2. 用户确认
print("请确认以下信息是否正确...")
```

### 🏗️ 集成优先
```python
# ❌ 不要这样做
edit_file(target_file="new_script.py", ...)

# ✅ 应该这样做
# 在现有文件中添加新方法
def new_feature(self):
    pass
```

## 📋 快速检查命令

```bash
# 1. 查看项目结构
ls -la

# 2. 检查相关文件
find . -name "*.py" | grep -i "feature"

# 3. 验证关键路径
python -c "from pathlib import Path; print(Path('path').exists())"
```

## 🆘 遇到问题时

1. **重新阅读需求**：确保理解完整
2. **分析项目状态**：检查现有功能和架构
3. **验证关键信息**：程序化验证 + 用户确认
4. **选择集成方式**：优先修改/扩展现有组件
5. **保持架构一致**：遵循现有的代码组织模式
